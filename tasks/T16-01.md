# T16-01  Read-only sign-in and audit mode

## Inputs
- SPEC §26; docs/spec-changes.md SC-26

## Outputs
- delegated device-code sign-in with read-only scopes as Global Reader; executor audit mode (test, verify, evidence only)

## Human steps
- None.

## Exit criteria
- In audit mode no plan or apply operation reaches a provider (test proves it).
- The sign-in requests no write scope.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).

## Status notes
- 2026-11-21: built. `box audit` signs in with the device code and the Microsoft Graph Command Line Tools client, requesting only the scopes in `expected-state/audit-scopes.yaml` (all `<Resource>.Read[.x]`; `TestAuditScopesAreReadOnly` fails on any ReadWrite, Send, Manage or FullControl scope). The token stays in memory and is dropped when the pack is written. `run.ModeAudit` runs test, verify and evidence only; `run.ReadOnlyInvoker` refuses plan and apply before they reach a provider (`TestAuditModeNeverPlansOrApplies`, `TestReadOnlyInvokerRefusesWrites`). The audit's own Graph client sends GET only (`audit.GetOnly`). Provider workers get the token only when it cannot write (by its scopes, or because the person holds only reader roles).
