# T8-01  Inbound mailbox (F14) and public forms (F15, F16)

## Inputs
- SPEC section 12
- SPEC §21 (inbound token), §22 gate G-04

## Outputs
- flows F14, F15, F16
- flows/forms/ definitions

## Steps
1. F14: accept only messages with a known type in the subject and the token in the body; parse JSON; dedupe on external id; write the row and InboundLog.
2. F15: NDA request form creates a DRAFT document for the legal role to confirm.
3. F16: privacy mail creates a request with its due date.

## Human steps
- Create the public forms (gate G-04). The inbound token is generated by the engine and stored per SPEC §21.

## Exit criteria
- A message without the token writes a refused InboundLog item and nothing else.
- The same lead id sent twice creates one lead.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
