# S-02  Write coverage of the Tenant Configuration Management APIs

## Inputs
- baseline/*.yaml

## Outputs
- spikes/findings/S-02.md
- expected-state/baseline-coverage.yaml

## Steps
1. For each setting in baseline/, determine: applied by the configuration APIs, monitored only, or neither.
2. For settings not writable, name the module and cmdlet or Graph call that applies it.
3. Create one monitor on the test tenant for a small baseline; change a setting by hand; confirm drift is reported; note the interval and daily resource limit.
4. Write expected-state/baseline-coverage.yaml: setting path, apply_by, monitor_by.

## Human steps
- None.

## Exit criteria
- Every setting in baseline/ has an apply_by and a monitor_by entry.
- A hand-made change was detected as drift, or the finding says monitoring must be done by `box drift`.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
