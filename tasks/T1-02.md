# T1-02  Users and licences

## Inputs
- configuration `users`
- configuration `tenant`

## Outputs
- command: box apply users

## Steps
1. Create or update users by id with usage location; assign the plan named; never assign a plan to `plan: none`.
2. New users get a Temporary Access Pass, not a password, delivered as the owner chose in step 6: on screen, or by email to a private address (SPEC §18.9). Passes and personal addresses are never logged.
3. `--plan` prints changes only. Export users and licences to evidence.

## Human steps
- None.

## Exit criteria
- Second apply reports no changes.
- Licence counts equal the configuration and never exceed the seats available.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).

## Status notes
- 2026-11-21, test tenant: `identity.users` adopts existing users, sets usage location and assigns plans within the seats available; second apply reports no changes. Issuing and delivering first sign-in passes for new users is done by the run view (T13-08), which owns delivery (SPEC §18.9).
