# T2-01  Shared mailboxes, lists and aliases

## Inputs
- configuration `mail` (recommended objects in defaults/mail.yaml)

## Outputs
- command: box apply mail

## Steps
1. Create shared mailboxes; block sign-in; add aliases; grant full access and send-as to the access group; enable copying sent items to the shared mailbox.
2. Create distribution lists with members, aliases and the external-senders setting.
3. Set auto-replies from configuration `mail.auto_replies`, rendered from the `Dictionary`, with the legal lines from `disclosures`.
4. Export all mail objects to evidence.

## Human steps
- None.

## Exit criteria
- Every address and alias in the file resolves.
- No shared mailbox holds a licence or allows sign-in.
- Second apply reports no changes.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).

## Status notes
- 2026-11-21, test tenant: exit criteria pass (all addresses and aliases resolve; shared mailboxes have no licence and sign-in blocked; second apply reports no changes). Waiting only on T1-03, which waits on T1-01 (gate G-02).
- Findings: Exchange accepts only mail-enabled groups for mailbox permissions, so Full Access and Send As go to the access group's members and are re-synced on every apply; Exchange refuses some words in group names ("postmaster"), so lists take an optional `display_name` while the address stays as configured.
