# T3-03  Register lists

## Inputs
- engine/register/lists.yaml

## Outputs
- command: box apply register
- command: box check register

## Steps
1. Create each list in the Admin site with columns mapped per SPEC section 7; lookups created after all lists exist; index id and lookup columns.
2. Append-only lists: grant add-only to the flow owner and read to owners.
3. Dictionary: edit for the owner role group. People: edit for owners. Other lists: read for staff where the specification allows, write by flows.
4. Create the standard views: Home (documents awaiting signature, in review, expiring), My approvals, Open items in Dictionary.
5. Seed Packages, PackageItems, Controls, ApprovalRules defaults and Dictionary (never overwriting an existing value).

## Human steps
- None.

## Exit criteria
- Lists and columns equal the definition.
- An owner cannot edit or delete an Events item.
- Seeding twice changes nothing.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).

## Status notes
