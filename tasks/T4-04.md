# T4-04  Content types and publication

## Inputs
- engine/register/lists.yaml (TemplateFields)
- configuration `structure.sites[].libraries`

## Outputs
- command: box apply templates

## Steps
1. Create site columns for every field and dictionary key used; one content type per template in the content type hub or per site as S-01 directs.
2. Attach the converted file as the content type's document template; add the content type to the libraries of its domain.
3. Add a matching list content type to Documents so its form shows that template's deal fields; mark never_store fields as absent from the list.
4. Upload converted templates to Legal/Templates with version; set Templates items ACTIVE; supersede earlier versions.

## Human steps
- None.

## Exit criteria
- New item in Documents offers one content type per ACTIVE signed template the user may see.
- The mutual NDA template's form shows counterparty fields and no company-constant field.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
