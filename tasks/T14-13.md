# T14-13  Frameworks list and selection by tick-box

## Inputs
- Frameworks list
- configuration `policy.frameworks`

## Outputs
- hourly scheduled job: list selection to configuration (SPEC §18.8)

## Steps
1. Load one Frameworks item per framework with coverage counts after each resolve.
2. When `selected` changes on the list, the pipeline app saves a new version of box-config.yaml with `policy.frameworks` changed and one Events item naming who changed it; it never applies anything.
3. The home screen shows the pending change with the coverage change and the settings, tasks and evidence schedules added or removed; the owner applies it through the plan.
4. A save from the TUI updates the list, so the two always agree. The tier is changed in the TUI only.

## Human steps
- None.

## Exit criteria
- Ticking a framework produces a new configuration version and one Events item within one run.
- Nothing changes on the tenant until the owner applies the plan.
- After a TUI save, the list and the configuration agree.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
