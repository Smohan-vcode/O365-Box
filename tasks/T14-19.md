# T14-19  Edge extensions installed for everyone (owner's choice)

Some extensions everyone needs (a company password manager, say). The
owner may choose to have Edge install approved extensions for everyone;
the recommendation is not to (SPEC §24, §25).

## Inputs
- choice `devices.browser_forced_extensions`: `none` (recommended; leaves
  WIN-091 and MAC-032 out) or `everyone` (supplies
  `devices.browser.forced_extensions`, empty at first)
- configuration `devices.browser.forced_extensions`: ids the owner marked
  "install for everyone" when approving a request (`box extensions approve
  <number> --install-for-everyone`, or `i` on the home screen); each must
  also be in `devices.browser.extension_allowlist` (`box config validate`)

## Outputs
- settings WIN-091 and MAC-032 (`Browser: extensions installed for
  everyone`, core tier, CFG-05) mapped to `ExtensionInstallForcelist`:
  Windows
  `device_vendor_msft_policy_config_microsoft_edge~policy~microsoft_edge~extensions_extensioninstallforcelist`
  (choice `_1`) with the string collection
  `..._extensioninstallforcelistdesc`; macOS
  `com.apple.managedclient.preferences_extensioninstallforcelist`. Both
  definitions read on the test tenant (200). They join the existing
  "Box - Windows - Microsoft Edge" and "Box macOS Edge" policies.

## Steps
1. An id alone installs from the Microsoft Edge Add-ons store (the default
   update URL). Edge force-installs only store extensions on devices that
   are not joined to an on-premises domain.
2. An empty list leaves the setting out (the definition takes at least one
   entry); Edge removes extensions it had force-installed when they leave
   the list.
3. Changing the choice from the home screen saves a new configuration
   version and plans the difference; nothing is applied without approval.

## Human steps
- None.

## Exit criteria
- `box policy resolve` with the choice `everyone` applies WIN-091 and
  MAC-032; with `none` both are left out with the choice as the reason.
- On the test tenant with the choice `everyone` and one forced id,
  `box check policy.intune-macos` passes after approve and apply, and a
  second apply plans no changes.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant:
  the policy setting read back and the step's `Setup` list item (SPEC §14).
