# T15-02  Domain control

## Inputs
- docs/spec-changes.md SC-23 B
- choice `domain.registrar`

## Outputs
- catalogue settings for domain control (verified domains, unverified domains reported, DNSSEC where free, CAA, null MX) tied to requirements
- gate `registrar-lockdown`

## Steps
1. Add the settings to the catalogue with requirements and framework references; map them (provider dns or identity).
2. Report stale unverified domains through Graph.
3. Registrar lock, two-step sign-in and auto-renew as a guided gate, checked by WHOIS status where the registrar exposes it.

## Human steps
- Lock down the registrar account (guided).

## Exit criteria
- Every domain setting is mapped or a gate.
- An unverified domain left in the tenant is reported as drift.

- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
