# T14-20  Report: Edge extensions in use

A read-only report of the Microsoft Edge extensions on company devices:
extension id, name, number of devices, and whether the tenant's Edge
policy allows, blocks or installs each.

## Inputs
- the live Edge policies "Box - Windows - Microsoft Edge" and "Box macOS
  Edge" (settings catalogue; DeviceManagementConfiguration, devices bundle)
- the installed extensions: Microsoft Graph exposes them only through
  Advanced hunting over Defender Vulnerability Management's
  `DeviceTvmBrowserExtensions` (`POST /security/runHuntingQuery`,
  `ThreatHunting.Read.All`, Defender Vulnerability Management add-on).
  Intune's discovered apps (`detectedApps`) do not list browser
  extensions; the Edge management service has no Graph API.
- the configuration's approved lists and the ExtensionRequests names

## Outputs
- `box extensions report [--out <dir>]`: the live policy per platform,
  one row per extension found or approved (devices, Windows, macOS,
  configuration), notes where the configuration's settings do not apply
  (for example WIN-069 outside the enhanced tier), and, when the inventory
  cannot be read, the reason and the proposed permission (never granted);
  `--out` writes `extensions-in-use.csv` and `.json` outside the repository
- audit pack: inventory `browser_extensions`, not read, with what it needs
  (the audit sends GET only; Advanced hunting is a POST)
- `upgrades/browser-extension-inventory.md`

## Steps
1. Read both Edge policies and extract the block, allow and install lists.
2. Run the Advanced hunting query; a refusal is "not read" with the reason.
3. Join with the approved lists and print the report.

## Human steps
- None. Reading the inventory needs the upgrade; the report proposes it.

## Exit criteria
- `box extensions report` on the test tenant prints both live policies and
  the approved extension, and says what the inventory needs.
- `go test ./...` covers reading the policy lists, a refused and a
  successful inventory read and the joined rows.
