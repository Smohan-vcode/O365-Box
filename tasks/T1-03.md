# T1-03  Groups and role groups

## Inputs
- configuration `groups` (recommended groups in defaults/structure.yaml)
- defaults/roles.yaml

## Outputs
- command: box apply groups

## Steps
1. Create security groups; generate `role-<name>` groups; seed membership from users.yaml.
2. Membership for people added later is owned by T6; this command never removes a member it did not add unless the person is inactive in People.

## Human steps
- None.

## Exit criteria
- All groups exist.
- Second apply reports no changes.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).

## Status notes
- 2026-11-21, test tenant: 6 access groups and 7 role groups exist with members; second apply reports no changes. A failed first run showed Graph's replication delay; the step no longer reads a group it has just created and refuses duplicate names.
