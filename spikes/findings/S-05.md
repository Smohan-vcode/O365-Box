# S-05 findings: Go orchestrator driving PowerShell providers

Date: 2026-11-21. Environment: Linux x64 container, pwsh 7.4.6, Go 1.24.
Answer: **yes**. The process-per-provider design in SPEC §3 holds and is
required.

## What was built

- `engine/providers/runtime/BoxWorker.ps1`: the worker host. One process per
  provider; requests on stdin, events on stdout, as JSON lines. Every
  protocol line starts with the marker U+001E `BOX:`, so stray console
  output from a module cannot corrupt the stream. It is kept and reported
  as a raw log line.
- `engine/internal/providers`: the Go supervisor (`Start`, `Call`, `Hello`,
  `Auth`, `Invoke`, `Close`, `Kill`).
- Tests: `worker_test.go` (protocol, logs, errors, credentials, timeouts,
  parallel start) and `spike_test.go` (measurements against the real
  modules, run with `BOX_MODULE_PATH`).

## Measurements

Each figure is the time from process start to the worker reporting ready,
with the module imported.

| Module | Version | Ready in | Round trip per call |
| --- | --- | --- | --- |
| Microsoft.Graph.Authentication | 2.25.0 | 0.43 s | 18 ms |
| ExchangeOnlineManagement | 3.6.0 | 0.93 s | 20 ms |
| PnP.PowerShell | 2.12.0 | 0.37 s | 24 ms |
| MicrosoftTeams | 6.7.0 | 1.20 s | 19 ms |
| All four in parallel | | 1.43 s | |

Bare pwsh starts in 0.23 s. Every provider is well under the 5 s target.

## Module conflicts

Each module bundles its own identity libraries:

| Module | Microsoft.Identity.Client | Microsoft.IdentityModel.Abstractions |
| --- | --- | --- |
| Microsoft.Graph.Authentication 2.25.0 | 4.61.3 | (loaded later) |
| PnP.PowerShell 2.12.0 | 4.64.0 | |
| MicrosoftTeams 6.7.0 | 4.62.0 | 6.35.0 |
| ExchangeOnlineManagement 3.6.0 | | 8.0.1 |

Connecting each module with an offline test token, which forces its
identity assemblies to load:

| Setup | Graph | PnP | Exchange |
| --- | --- | --- | --- |
| One shared process (Graph, then PnP, then Exchange) | ok | ok | **MissingMethodException** in `Microsoft.IdentityModel.JsonWebTokens` |
| One process per module | ok | ok | ok (got as far as the network, which this test environment blocks) |

The shared-process failure is a real version clash: two copies of
Microsoft.Identity.Client end up loaded, and Exchange then binds to an
incompatible IdentityModel. **Never load two Microsoft modules in one
worker.** The step manifest assigns each step to exactly one provider.

MicrosoftTeams rejects an offline token (NullReferenceException while
parsing claims), with or without other modules. It cannot be exercised
without a real tenant token. S-06 and S-08 verify it on the test tenant.

## Credential passing

- Credentials are sent only in an `auth` request over stdin and kept in
  worker memory.
- The worker gets a minimal environment, built by `baseEnv`. The test
  checks that a token appears in neither `/proc/<pid>/cmdline` nor
  `/proc/<pid>/environ`, nor in any regular file under the worker's HOME
  and TMPDIR.
- Every credential value (six characters or more) is redacted as
  `[redacted]` from log, progress, result and error text. The test step
  deliberately prints and throws the token, and only the redacted form
  reaches the orchestrator.
- Providers read credentials with `Get-BoxAuth <name>`.

## Behaviour confirmed by tests

- Write-Host, Write-Information, Write-Warning and Write-Verbose become
  `log` events with levels. Direct `[Console]::WriteLine` output becomes a
  raw line, and the protocol stays intact.
- A thrown error becomes an `error` event, and the worker stays usable.
- A call whose context expires kills the worker. Later calls fail with
  `ErrClosed`, so the orchestrator restarts the provider for the next step.
- A missing provider module or Microsoft module fails start-up with the
  module named in the error.
- Relative module paths are read by PowerShell as module names, so the
  supervisor passes absolute paths.
- .NET creates named pipes in TMPDIR. Anything that sweeps a worker's temp
  directory must open regular files only.

## Consequences for dependent tasks

- T0-02 and T0-03 use this protocol unchanged. Step manifests name one
  provider per step.
- Pinned versions are in `expected-state/modules.yaml`, for `box doctor`.
- PnP.PowerShell 3.x needs PowerShell 7.4 and a tenant's own app
  registration. That suits our pipeline app, but 2.12.0 is pinned until
  S-06 confirms app-only sign-in with a certificate.
- The PowerShell Gallery must be reachable to install the modules. The
  environment `o365-box` allows www.powershellgallery.com and
  cdn.powershellgallery.com.
