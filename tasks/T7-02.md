# T7-02  Drift monitors and weekly report

## Inputs
- expected-state/baseline-coverage.yaml

## Outputs
- command: box drift
- monitors created as code

## Steps
1. Create configuration monitors for every setting the coverage file marks as monitorable, within the daily resource limit.
2. `box drift`: read monitor results; run every step's `plan` for the rest: users, groups, mail objects, sites, libraries, list schema, flows present and on, DNS.
3. Set DRIFTED on affected Setup items; mail the weekly report to alerts; store it as evidence.

## Human steps
- None.

## Exit criteria
- A hand-changed setting is reported and its step shows DRIFTED.
- A clean tenant yields an empty report.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
