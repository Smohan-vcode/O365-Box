# T14-16  Standards rendered from requirements

## Inputs
- policy/requirements.yaml
- `Dictionary` (company values)

## Outputs
- command: box render standards
- one standard per domain in the Compliance site's `Policies` library

## Steps
1. Render one standard per domain: requirement id, statement, how it is enforced (setting names), evidence, framework references.
2. Policies in defaults/policies/ cite requirement ids instead of repeating rules.
3. Publish through the same route as policies (T9-01, T9-02); never overwrite a version edited in the library.

## Human steps
- None.

## Exit criteria
- Every requirement appears in exactly one standard.
- Changing a requirement changes the rendered standard on the next render.
- Nothing is rendered into the repository; templates pass check-literals.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
