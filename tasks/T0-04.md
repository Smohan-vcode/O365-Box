# T0-04  Sign-in, discovery and bootstrap

## Inputs
- SPEC §18.2, §18.3, §18.5, §21
- expected-state/bootstrap-scopes.yaml, expected-state/app-permissions.yaml

## Outputs
- engine/internal/auth
- bootstrap step group
- command: `box check identity`
- runbooks rendered from gate definitions

## Steps
1. Browser sign-in with PKCE on localhost and device-code fallback, with the Graph Command Line Tools client.
2. Discovery: token claims, organization, domains, subscribed plans, users and groups, NS records, security defaults and Conditional Access state.
3. Bootstrap per SPEC §18.5: domains, pipeline app, app role assignments, Entra roles, federated credential, certificate in the keychain, break-glass accounts and group, gate G-02.
4. Discard the Global Administrator token after bootstrap; prove it is not on disk.
5. `box check identity`: granted permissions and roles equal the expected file; no client secret; nothing from `never`.
6. Render runbooks/00-bootstrap.md from the gate definitions.

## Human steps
- G-00 or a test tenant; G-02 security keys.

## Exit criteria
- Bootstrap on the test tenant creates the app with exactly the listed permissions; a second run changes nothing.
- Adding an unlisted permission makes `box check identity` fail.
- No Global Administrator token is found on disk after the run.
- Browser sign-in with PKCE on localhost works on Windows, macOS and Linux (moved from S-08), and device code works where no browser is available.
- The sign-in guide covers AADSTS165000 (lost browser cookies) and shows only one live device code (S-08).

- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
