# T0-02  Orchestrator: step contract, graph, state and events

## Inputs
- SPEC §14
- spikes/findings/S-05.md

## Outputs
- engine/internal/{plan,run,state,events,gates}
- provider step manifest schema (engine/providers/*/steps.yaml)
- commands: `box plan`, `box up`, `box status`, `box drift`, `box apply <step>`, `box check <step>`, `box gate <id> [--check]`

## Steps
1. Define the step contract (test, plan, apply, verify, evidence) and the manifest schema.
2. Build the step graph from manifests and enabled modules; fail on unknown or cyclic dependencies and on capabilities with no fallback.
3. Executor: parallel independent steps, retries with backoff, resume (skip steps whose plan is empty and verify passes), gates that poll their check.
4. Event stream as JSON lines; a writer for the local cache; a redactor that drops `never_store` fields and secrets.
5. A fake provider for tests that records calls.

## Human steps
- None.

## Exit criteria
- A run interrupted mid-way resumes at the first incomplete step.
- A step whose dependency failed is not started.
- No secret or `never_store` value appears in any event in the test suite.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
