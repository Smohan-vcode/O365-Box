# S-06 findings: bootstrap with a delegated Global Administrator session

Date: 2026-11-21. Test tenant: Business Premium, new, security defaults on.
Answer: **yes**. Every bootstrap action in SPEC §18.5 works through Graph
with the Graph Command Line Tools client and the delegated scopes in
`expected-state/bootstrap-scopes.yaml`. No admin centre step is needed,
except DNS control for domain verification, which is gate G-06 or the
DNS adapter (T2-03).

## Run

`box spike-tenant --write` (engine/internal/cli/spike.go) with
`engine/internal/bootstrap`. It created a throwaway application, exercised
each action, and removed everything afterwards.

| Action | Graph call | Result |
| --- | --- | --- |
| Device-code sign-in as Global Administrator; consent to all bootstrap scopes | `/oauth2/v2.0/devicecode`, `/token` | ok; token tenant matches; every requested scope granted |
| Create application (single tenant) | `POST /applications` | ok |
| Create service principal | `POST /servicePrincipals` | ok (waited 10 s for replication before the next call) |
| Grant an application permission (admin consent) | `POST /servicePrincipals/{graph}/appRoleAssignedTo` | ok (`Organization.Read.All`) |
| Assign an Entra role | `POST /roleManagement/directory/roleAssignments` (template id, scope `/`) | ok (Exchange Administrator) |
| Add GitHub federated credential | `POST /applications/{id}/federatedIdentityCredentials` | ok |
| Add certificate (private key kept in memory) | `PATCH /applications/{id}` keyCredentials | ok |
| Check credentials | `GET /applications/{id}` | 0 client secrets, 1 certificate |
| Add domain; read verification records | `POST /domains`, `GET …/verificationDnsRecords` | ok; record types TXT and MX |
| Verify domain without DNS record | `POST /domains/{id}/verify` | fails as expected (HTTP 400, "Error in DNS verification") |
| Clean up: delete domain, remove role assignment, delete and purge application | `DELETE …`, `DELETE /directory/deletedItems/{id}` | ok |

## Consequences for T0-04

- Bootstrap composes these calls in `engine/internal/bootstrap`. They are
  in place and exercised against a real tenant.
- Allow for replication: retry the first call that uses a new service
  principal (a short wait was enough here).
- Domain verification needs the DNS record to exist first. The DNS adapter
  writes the TXT record (T2-03), or gate G-06 asks the owner to. Then
  `VerifyDomain` is retried until it passes. The error for a missing
  record is a generic HTTP 400, so retries treat any 400 as "not yet".
- Delete purges from the recycle bin (`/directory/deletedItems`), so a
  re-run does not collide with a soft-deleted app of the same name.
- The token never left process memory. Results with tenant values were
  written outside the repository.
