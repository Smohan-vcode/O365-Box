# S-02 findings: Tenant Configuration Management APIs

Date: 2026-11-21. Test tenant, Business Premium, pipeline app with the
permissions in `expected-state/app-permissions.yaml`.

Answer: **the APIs can monitor and snapshot, not apply; they are not usable
yet with the granted permissions.** Settings are applied by provider
steps. Drift is monitored by `box drift` (every step's verify) until the
configuration-monitor API is adopted (SC-20, proposed).

## What was checked (read-only)

| Check | Result |
| --- | --- |
| `GET /beta/admin/configurationManagement/configurationMonitors` | HTTP 403 for the pipeline app |
| `GET /beta/admin/configurationManagement/configurationSnapshotJobs` | HTTP 403 for the pipeline app |
| Graph application permissions offered | `ConfigurationMonitoring.Read.All`, `ConfigurationMonitoring.ReadWrite.All` exist; neither is granted |
| The service's own service principal (application id 03b07b79-c5bc-4b5e-9bfa-13acf4a99998) | not present in the tenant |

## What adopting it would need

1. `ConfigurationMonitoring.ReadWrite.All` for the pipeline app (new
   permission; proposed as SC-20, not granted).
2. A Global Administrator adds the service's service principal to the
   tenant and grants it the read permissions and Entra roles for each
   workload it monitors (Graph policy reads, Exchange, Teams, Purview).
   This is a bootstrap addition, run in the same sign-in as `box bootstrap`.
3. Monitors are created per resource type from the resolved settings. The
   API is in preview (beta) with daily resource limits per tenant; the
   limits apply to monitored resources, so monitors would cover the
   settings it supports and `box drift` the rest.

The monitors only report drift: they never change the tenant. Applying
stays with the provider steps (SPEC §14), so nothing in the apply path
depends on this preview API.

## Consequences

- `expected-state/baseline-coverage.yaml` gives, for every setting,
  `apply_by` (provider step and method, a gate, or unresolved) and
  `monitor_by` (`box drift`, plus the configuration-monitor resource type
  where one is known, usable after SC-20). Generated from
  `expected-state/setting-ids/*.json` (T14-03).
- Step 3 of this spike (create a monitor, change a setting by hand, see
  the drift) could not run without the permission. The exit criterion's
  alternative applies: monitoring is done by `box drift`, which T14-04 and
  T7-02 rely on. A hand-made change detected by `box drift` was shown on
  the test tenant in earlier runs (identity, mail and SharePoint steps).
