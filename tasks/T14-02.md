# T14-02  Capability check against tenant licences

## Inputs
- SPEC §18.3, §20.3, §23
- policy/capabilities.yaml
- engine/capabilities.yaml
- discovery: subscribed SKUs and service plans

## Outputs
- engine/capabilities.yaml: every policy capability key, with the service plans that provide it
- read-only step `policy.capabilities`; command: box check policy.capabilities

## Steps
1. Reconcile the capability keys: every key in `policy/capabilities.yaml` exists in `engine/capabilities.yaml` with the plans that include it; `box policy validate` fails on a key missing there. Keep one plan map (R11).
2. With the pipeline app, read the tenant's subscribed products and service plans; record, for each capability key, the Microsoft service plan that provides it (engine data, the same for every tenant); confirm with one read-only probe call per capability that the feature is usable.
3. Report users whose plan lacks a capability that resolved settings need; they are outside those settings and are listed on the Review screen and in the coverage report.
4. Fail if the resolved settings contain one whose capability the tenant lacks.

## Human steps
- None.

## Exit criteria
- Every capability marked included for the tenant's plan is confirmed usable, or the finding names the one that is not and the settings affected.
- A user on a lower plan is listed as not covered.
- No tenant-specific value is written to `engine/capabilities.yaml`.

## Evidence
- Engine: front matter `status: DONE` with the commit reference. Tenant: the step's `Setup` list item and evidence artefact (SPEC §14).
